常见问题 ​

汇总 README 与源码中最容易让人困惑的问题。涉及具体文件时都给出了对应章节链接。

Node 到底需要哪个版本？ ​

以 package.json 的 engines 为准：^20.19.0 || >=22.12.0，即 Node 20.19+ 或 22.12+。README 安装章节里的「Node 16+ / 18+」是旧描述，Vite 7 已不支持这些版本。用 node -v 检查一下即可。详见快速开始。

需要会后端开发吗？ ​

不需要。README 明确说明这是纯前端仓库，代码与部署都可以前后端分离，前端开发者无需掌握后端代码。对接真实服务时配置 VITE_API_URL 与 /api 代理即可，见环境与配置。

演示账户是什么？能改数据吗？ ​

账户 admin，密码 123456。README 注明演示站数据无法修改，想体验完整功能请下载源码本地安装。另外，README 里的「演示站」链接实际指向 Gitee 仓库，并非独立线上 Demo，见联系与演示。

可以免费商用吗？ ​

可以。项目遵循 Apache-2.0 协议，无需授权即可免费使用；第三方源码与二进制文件的版权信息另行标注。分发时记得保留许可证与版权声明，见版权与许可。

用 npm 还是 pnpm？ ​

推荐 pnpm（README 徽章建议 ≥ 10.13.1）。项目带 pnpm-lock.yaml 与 pnpm-workspace.yaml，混用包管理器容易造成依赖版本漂移。

端口 9094 可以改吗？ ​

可以，修改根目录 .env 的 VITE_PORT 后重启。端口被占用时 Vite 会自动尝试下一个可用端口（strictPort: false），注意看终端打印的实际地址。

README 里的项目预览图在哪？ ​

README 的「项目预览」章节目前只有标题、顶部也只有一段 img 占位文本；仓库 src/assets/readme/ 下仅有 logo.png，没有界面截图。想看实际界面，请按快速开始在本地运行项目。

为什么 README 说有 web 文件夹，仓库里找不到？ ​

那是旧版目录结构的描述。当前版本的 干净/完整 前端代码直接位于根目录 src/，不存在 web 目录。以目录结构为准。

徽章写 Vite > 6.0，为什么依赖里是 7.x？ ​

徽章表达的是最低版本门槛，实际锁定版本更高：Vite ^7.1.2、Pinia ^3.0.3、TypeScript ~5.8.3、Element Plus ^2.10.7。升级插件时注意 Vite 7 / Pinia 3 的大版本变化，完整对照见技术栈与依赖。

接口请求 404 或跨域怎么办？ ​

两处一起检查：.env.* 中的 VITE_API_URL，以及 build/vite/server.ts 里 /api 代理的 target（当前为空字符串，需要填你的后端地址）。

路由是 history 还是 hash 模式？ ​

当前使用 createWebHashHistory()，地址带 #/。静态部署时通常不会出现 history 模式的刷新 404 问题；若页面空白，先确认访问地址包含 #/ 且托管服务正确返回 index.html。

无限子级权限已经做好了吗？ ​

README 把它列为目标特性。当前仓库可见的是静态路由自动收集（import.meta.glob）+ 登录白名单，完整的「权限树 → 动态注册路由 → 按钮级鉴权」链路尚未在源码中闭环，部分相关代码处于注释状态。详见路由与权限。

为什么 pnpm run dev 正常但 build 报错？ ​

build 会先执行 vue-tsc -b 做全量类型检查，开发模式不会。按报错修复类型问题即可，见环境与配置。
