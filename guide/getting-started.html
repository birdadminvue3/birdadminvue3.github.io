快速开始 ​

从零把 BirdAdmin 跑起来只需要四条命令。本章在 README 安装步骤的基础上，补齐了环境要求、验证方式与常见排错。

1. 准备环境 ​

工具要求说明
Node.js^20.19.0 || >=22.12.0来自 package.json 的 engines 字段
pnpm建议 ≥ 10.13.1README 徽章标注的推荐版本
Git任意较新版本用于克隆仓库

README 中的 Node 版本描述已过时

README 的安装章节写着「现在你必须使用 Node 16+ / 18+ 版本」，但当前 package.json 的 engines 已经要求 ^20.19.0 || >=22.12.0，且 Vite 7 本身也不再支持旧版 Node。请以 engines 为准，使用 Node 20.19+ 或 22.12+。

可用 node -v 检查当前版本；多版本管理推荐使用 nvm-windows、fnm 或 Volta。

2. 克隆与安装 ​

bash
# 克隆项目
git clone https://gitee.com/web_akai/bird-admin.git

# 进入项目
cd bird-admin

# 安装 pnpm（已安装可跳过）
npm i -g pnpm

# 安装依赖
pnpm install

pnpm install 会按照根目录的 pnpm-lock.yaml 还原依赖，建议不要删除锁文件，也不要混用 npm / yarn 安装，以免出现依赖版本漂移。

3. 启动开发服务器 ​

bash
pnpm run dev

该命令等价于 vite。根据 .env 中的配置，默认端口为 9094；build/vite/server.ts 里设置了 host: true（允许局域网访问）和 strictPort: false（端口被占用时自动尝试下一个可用端口）。

启动成功后浏览器访问 http://localhost:9094/。项目使用 hash 路由，地址形如 http://localhost:9094/#/login。

想改端口？

修改根目录 .env 中的 VITE_PORT 后重启开发服务器即可。详见环境与配置。

4. 打包发布 ​

bash
pnpm run build

该命令实际执行 vue-tsc -b && vite build：先做 TypeScript 类型检查，再进行生产构建。因此类型报错会导致打包中断，这是刻意设计的质量门禁。

构建产物默认输出到 dist/，可直接部署到 Nginx、对象存储或各类 Pages 静态托管服务。若部署在子路径下，需同步调整 VITE_BASE_PATH。

本地预览构建结果：

bash
pnpm run preview

5. 登录体验 ​

README 提供的演示账户：

项值
账户admin
密码123456

演示站数据无法修改，请下载源码安装体验全部功能。

本地开发时，mock/login.ts 配合 vite-plugin-fake-server 提供了登录假数据，即使没有后端也能走通流程。

常见问题排查 ​

pnpm install 报 Node 版本不支持 先执行 node -v，确认满足 ^20.19.0 || >=22.12.0。部分依赖（Vite 7、UnoCSS 66）对 Node 版本有硬性要求。

端口 9094 被占用strictPort: false 会让 Vite 自动换到下一个可用端口，留意终端实际打印的地址；也可以直接修改 VITE_PORT。

构建时 TypeScript 报错pnpm run build 会跑 vue-tsc -b。先修复类型错误，或临时用 pnpm run dev 继续开发（开发模式不做全量类型检查）。

接口请求 404 / 跨域build/vite/server.ts 中的 /api 代理 target 默认为空字符串，需要按你的后端地址填写；同时核对 .env.* 中的 VITE_API_URL。

页面刷新后空白 项目使用 createWebHashHistory()，请确认访问地址包含 #/，且静态托管服务已正确返回 index.html。
