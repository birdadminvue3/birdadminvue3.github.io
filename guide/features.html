主要特性 ​

README 用六个小节描述了 BirdAdmin 的核心特性。本章保留原文要点，并补充当前仓库中可以核对的细节。

特性一句话概括当前可核对的实现
👍 流行稳定的技术栈主流方案，生态成熟Vue 3.5 / Vite 7 / TS 5.8 / Element Plus 2.10 / Pinia 3
🔀 前后端分离纯前端仓库，独立部署.env* 中的 VITE_API_URL 与 /api 代理
✨ 高颜值三种布局，无边框设计layout/、主题与尺寸配置

👍 流行且稳定的技术栈 ​

除了基于 Node.js 前后端分离架构外，我们的 Vue3 使用了 setup、useTemplateRef 等，状态管理使用 Pinia，并使用了 TypeScript、Vite 等可以为你的知识面添砖加瓦的技术栈。使用流行技术栈自然代表本框架兼容相关（Vue3+Nodejs+Koa2）生态，生态系统内数不清的库、包、组件，能够使您的开发事半功倍。

选型全部落在主流生态内：Vue 3 组合式 API（setup、useTemplateRef）、Pinia 状态管理、TypeScript 类型约束、Vite 构建、Element Plus 组件库，再配合 UnoCSS、VueUse、Axios 等工具。

好处是遇到问题几乎都能在社区找到答案，团队接手成本低。完整版本清单见技术栈与依赖。

🔀 前后端分离 ​

项目的 web 文件夹内包含：干净（不含后端代码）、完整（所有前端代码文件均在此内）的前端代码文件，代码和部署均可前后分离，对前端开发者友好。作为纯前端开发者，您可以将 BAdmin 当做学习与资源的社群，本系统可为您准备好案例和模板等所需要的环境，而您只需专注于学习或工作，不需要会任何后端代码！

当前仓库就是一份不含后端代码的前端工程：接口地址通过 VITE_API_URL 配置，开发服务器提供 /api 代理，本地还能用 mock/ 下的假数据独立调试登录流程。

关于 README 中的 web 文件夹

当前 Gitee 仓库根目录下并没有 web 目录，前端代码直接位于 src/。阅读旧版说明时请以目录结构为准。

✨ 高颜值 ​

提供三种布局模式，其中默认布局使用无边框设计风格，它并没有强行填满屏幕的每一个缝然后使用边框线进行分隔，所有的功能版块，都像是悬浮在屏幕上的，同时又将屏幕空间及其合理的利用了。

界面层由 layout/ 承载，并提供深浅色主题（默认跟随操作系统 prefers-color-scheme）、组件尺寸、语言与水印等设置项，统一由 store/modules/settings.ts 与 config/index.ts 管理。

🔐 权限验证 ​

可视化的管理权限，然后根据权限动态的注册路由、菜单、页面、按钮（权限节点）、支持无限父子级权限分组、前后端搭配鉴权，自由分派页面和按钮权限。

这是 BirdAdmin 最被强调的能力：菜单与按钮不再写死，而是由权限数据动态生成，前后端配合完成鉴权。

当前仓库里可以直接看到的基础设施包括：

  • router/index.ts 使用 import.meta.glob 自动收集 router/modules/**/*.ts，无需手动引入路由模块；
  • 使用 createWebHashHistory() 的 hash 路由，部署到静态托管更省心；
  • 路由前置守卫 router.beforeEach 与白名单 ["/login"]，用于登录态校验；
  • utils/auth.ts 提供认证相关工具函数。

更多细节见路由与权限。

📝 未来可期 ​

我们正在持续维护系统，并着手开发更多基础设施模块，按需一键安装，甚至提供开箱即用的各行业完整应用。

项目 README 明确说明仍在持续维护，并规划按需安装的基础设施模块与行业应用。使用或关注项目时，建议以 Gitee 仓库的最新提交为准。

💖 其他杂项 ​

系统配置/控制台/个人资料管理等等、更多特性等你探索...

src/config/index.ts 中已包含系统标题、版本、主题、组件尺寸、语言、水印等默认设置；utils/console.ts 负责控制台输出；views/login 提供登录页。其余模块欢迎在仓库中自行探索。
