路由与权限 ​

README 把「自动注册路由」和「无限子级权限管理」列为 BirdAdmin 的核心能力。本章把 README 描述的目标 与 当前仓库可见的实现 分开说明，方便你判断哪些已经能用、哪些还需要自己补。

当前可见的路由实现 ​

核心逻辑集中在 src/router/index.ts：

ts
// 自动导入全部静态路由，无需再手动引入
const modules: Record<string, any> = import.meta.glob(
  ["./modules/**/*.ts", "!./modules/**/staticRoutes.ts"],
  { eager: true }
)

const routes = []
Object.keys(modules).forEach(key => {
  routes.push(modules[key].default)
})

export const constantRoutes: Array<RouteRecordRaw> = routes

export const router = createRouter({
  history: createWebHashHistory(),
  routes: constantRoutes.concat(...(staticRoutes as any)),
  strict: true,
  scrollBehavior: () => ({ left: 0, top: 0 })
})
机制说明
模块自动收集import.meta.glob 扫描 router/modules/**/*.ts，排除 staticRoutes.ts，新增路由文件后无需手动 import
路由模式createWebHashHistory()，地址带 #/，对静态托管友好
静态路由staticRoutes.ts 单独维护，staticPaths 收集「不参与菜单的路由」
路由白名单const whiteList = ["/login"]
导航守卫router.beforeEach 用于登录态校验，配合 utils/progress 的 NProgress 进度条
滚动行为每次导航回到页面顶部

代码中被注释的部分

router/index.ts 里关于 formatTwoStageRoutes、buildHierarchyTree、用户信息读取、keepAlive 缓存、document.title 设置、externalLink 判断等代码块目前处于注释状态，另有一处 VITE_HIDE_HOME 环境变量引用并未在 .env* 中定义。这些是后续扩展的占位，不要误以为已经生效。

添加自己的页面 ​

按现有约定，大致流程是：

  1. 在 src/views/ 下新建页面组件；
  2. 在 src/router/modules/ 下新增一个 .ts 路由模块并 export default（该文件会被自动收集）；
  3. 如果是登录页、404 这类不出现在菜单中的路由，放进 staticRoutes.ts；
  4. 需要登录态保护时，检查 beforeEach 中的白名单逻辑；
  5. 接口定义在 src/api/，请求走 src/utils/http / src/utils/request。

关于动态权限 ​

README 描述的完整形态是：

可视化的管理权限，然后根据权限动态的注册路由、菜单、页面、按钮（权限节点）、支持无限父子级权限分组、前后端搭配鉴权，自由分派页面和按钮权限。

要实现它，通常需要后端返回权限节点树，前端在登录后调用 router.addRoute() 动态注册，并在菜单组件与按钮级指令 / v-if 中做鉴权。

当前仓库可见的代码以静态路由自动收集 + 登录白名单为主，store/modules/user.ts 与 utils/auth.ts 提供了基础状态与工具，但完整的「权限树 → 动态路由 → 按钮鉴权」链路尚未在源码中闭环。如果你的项目强依赖这块能力，建议先通读 router/index.ts 与 store/modules/，再按上面的思路自行补齐，或关注仓库后续更新。

别把规划当现状

这类模板项目的 README 往往同时描述「已实现」和「规划中」。判断标准很简单：在 src/ 里能搜到对应实现再用，搜不到就自己写。
