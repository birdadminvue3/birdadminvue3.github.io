环境与配置 ​

BirdAdmin 使用 Vite 标准的 .env 文件体系，并在 build/vite/server.ts 中定义开发服务器行为。本章整理当前仓库的真实配置值。

环境变量 ​

变量.env.env.development.env.production用途
VITE_BASE_PATH///部署基础路径（vite.config.ts 中的 base）
VITE_PORT9094——开发服务器端口
VITE_API_URL—https://gitee.comhttps://gitee.comAPI 地址前缀
VITE_DROP_CONSOLE—truefalse构建时是否移除 console

.env 为通用配置，.env.development 在 pnpm run dev 时加载，.env.production 在 pnpm run build 时加载。只有 VITE_ 前缀的变量才会暴露给客户端代码。

注意：注释文案与文件名疑似对调

当前仓库中 .env.development 的头部注释写的是「【生产】环境变量」且 VITE_DROP_CONSOLE = true，而 .env.production 写的是「【开发】环境变量」且 VITE_DROP_CONSOLE = false。两处注释与开关值看起来与文件名相反。

请以文件名判断生效环境；在正式发布前，建议确认生产构建是否需要移除 console，并据实调整这两个值，同时把 VITE_API_URL 改成你自己的后端地址（当前示例值为 https://gitee.com）。

常用修改 ​

修改端口（.env）：

dotenv
VITE_PORT = 9094

部署到子路径：把对应环境文件的 VITE_BASE_PATH 改为 /你的目录名/，构建产物才能正确加载静态资源。若只是部署文档站到 Pages 子路径，改的是文档站 config.mts 中的 base，两者不要混淆。

对接后端 API：设置 VITE_API_URL，并按下一节配置 /api 代理。

开发服务器与代理 ​

build/vite/server.ts 的关键设置：

配置值含义
hosttrue允许局域网访问
portNumber(VITE_PORT)读取 .env 中的端口
strictPortfalse端口占用时自动尝试下一个可用端口
proxy['/api']target: ''代理目标默认为空，需自行填写后端地址

代理规则会把 /api 前缀重写掉：

ts
proxy: {
  '/api': {
    target: '',                                  // ← 填你的后端地址
    changeOrigin: true,
    rewrite: path => path.replace(/^\/api/, ''),
  },
}

脚本命令 ​

来自 package.json：

命令实际执行说明
pnpm run devvite启动开发服务器
pnpm run buildvue-tsc -b && vite build先类型检查，再生产构建
pnpm run previewvite preview本地预览 dist/ 产物

构建失败先看类型

pnpm run build 比 pnpm run dev 多了 vue-tsc -b 这一步，很多「本地能跑、打包报错」都源于此。建议开发过程中定期跑一次构建。
